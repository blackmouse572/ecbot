faq:
  - q: Which file types can I upload?
    a: File items take PDF, Word (DOCX), plain text, HTML and Markdown, up to 5 MB. Media items take JPG, PNG and WEBP images up to 5 MB and PDFs up to 20 MB, up to 50 files at a time. For a web page, add its public URL. For short facts, add a text note.
  - q: Why does my item still say Draft?
    a: An item is only used after it is processed. Open the item's menu and choose Process, then wait until the status shows Completed.
  - q: Do customers see my file names?
    a: No. Customers get the answer only. Source references show in your own test chat so you can check where an answer came from.

The knowledge base is where you put the documents your agent answers from: price lists, product sheets, return policies and FAQs. Each item is processed once, then linked to one or more agents. For every question, the agent looks up the relevant part of your documents, so it quotes your facts instead of guessing.

## Add an item

Open **Knowledge Base** under **Agents** in the sidebar.

| Type | Use it for | Limits |
| --- | --- | --- |
| **File** | Documents your agent answers from and never sends: price lists, policies, product sheets. | PDF, DOCX, TXT, HTML or MD, up to 5 MB. |
| **URL** | A public web page your agent reads, and the pages it links to on the same site. | Up to 50 pages per item. The page must open without signing in. |
| **Text** | A short note you type. | Text only. |
| **Media** | Images and PDFs your agent sends to customers: product photos, banners, a PDF menu. | JPG, PNG or WEBP up to 5 MB, PDF up to 20 MB, up to 50 files at a time. |

Media items are made for sending: each uploaded file becomes its own item, named after the file, and your agent sends it as its own message when a customer asks to see it (an image as a photo, a PDF as a file). Processing a Media item uses vision AI: about 2,000 tokens per image, and about 500 per picture page in a PDF (pages that are mostly text are read without vision). That counts toward your plan's AI quota, see [Usage](/docs/agents/usage).

A URL must be publicly reachable; pages behind a login or on your own computer cannot be read. Use **Folders** and **Tags** to keep a large knowledge base in order.

| Status | Meaning |
| --- | --- |
| **Draft** | Saved but not processed. The agent does not use it yet. |
| **Ready** / **Processing** | Queued or being split and indexed. |
| **Completed** | Processed and ready for linked agents. |
| **Failed** | Could not be read. Check the file or URL, then process it again. |

## Link items to an agent

Open the agent's page, go to the **Knowledge Base** section and choose **Add**. Pick the items this agent should use. An agent only answers from the items linked to it.

## Keep it current

When a price or policy changes, edit the item and process it again. Short facts that change often (opening hours, delivery fee) can live in the agent's business facts instead, see [Agent builder](/docs/agents).
